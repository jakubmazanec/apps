# UI Theme Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Declare the game's appearance once as a theme, consume it directly in widgets, and delete every game-code helper that assembles widgets from parts.

**Architecture:** A `UiThemeDescription` literal naming atlas frames is declared at module load in game code and passed through `GameOptions`. `Game.init()` resolves it to a `UiTheme` of real textures immediately after the default bundle loads. Widgets accept the resolved theme and build their own backgrounds from it, choosing `NineSliceSprite` or `Sprite` based on whether the texture carries `defaultBorders`. Separately, `GameAssets` gains a `spriteset()` lookup so engine `Sprite` can take a resolved `Spriteset` instead of calling `pixi.Assets` itself.

**Tech Stack:** TypeScript, pixi.js 8.16.0, `@pixi/layout` 3.2.0, vitest + happy-dom.

**Spec:** `docs/superpowers/specs/2026-07-30-ui-theme-design.md`

## Global Constraints

- Working directory for all commands is `apps/somewhere`.
- **`GameAssets` returns only shared, cached assets.** It constructs no display objects and gains no factory methods.
- **`Game` is the engine's only seam onto `GameAssets`** (`Game.ts:43`). No widget, no `Sprite`, no other engine class gets a handle; they receive resolved assets.
- **Backgrounds are owned per widget.** Background instances are never shared and never stored in the theme. Only textures live in the theme.
- **In `GameAssets`, `pixi.Assets.cache.has(name)` must be checked before `pixi.Assets.get(name)`.** This avoids a pixi cache warning and is pinned by `tests/GameAssets.test.ts:132-139`.
- **Every frame named in the theme description must live in the `default` bundle**, the only bundle loaded when resolution runs.
- Error message style is `Thing "x" <problem>!` — match the existing strings in `GameAssets.ts`.
- Code style: `let` for locals (not `const`), `#private` class fields, `readonly` where applicable. Match surrounding code.
- **Out of scope** — do not touch: typed asset keys (frame names stay `string`), `tilemap()`/`tileset()` accessors, `Map.ts:40`, `Tilemap.ts:258`, `world.ts:116`, `audioSystem.ts:16`, `dialogueBoxSystem.ts:98`, `TextInput.ts:117`.

`pixi.js` wholesale, so `pixi.Texture`, `pixi.Sprite` and `pixi.NineSliceSprite`
do **not** exist inside them:

Because of this, **widget tests must not assert on `Sprite` vs `NineSliceSprite`.**

```ts
  // The cache check precedes Assets.get so a miss never triggers pixi's cache
  // warning.
  #resolveSpriteset(name: string): Spriteset {
    if (!pixi.Assets.cache.has(name)) {
      throw new Error(`Spriteset "${name}" wasn't loaded!`);
    }

    let asset = pixi.Assets.get<unknown>(name);

    if (!(asset instanceof Spriteset)) {
      throw new Error(`Asset "${name}" is not a spriteset!`);
    }

    return asset;
  }

  spriteset(name: AssetNames<Bundles, 'spritesets'>): Spriteset {
    return this.#resolveSpriteset(name);
  }

  texture(spriteset: AssetNames<Bundles, 'spritesets'>, frame: string): pixi.Texture {
    let texture = this.#resolveSpriteset(spriteset).textures[frame];

    if (!texture) {
      throw new Error(`Texture "${frame}" not found in the "${spriteset}" spriteset!`);
    }

    return texture;
  }
```

- [ ] **Step 3: Write the implementation**

```ts
import * as pixi from 'pixi.js';

// The atlas decides whether a piece of art is nine-sliced: insets ship as
// per-frame `borders` in the spriteset JSON and reach the texture as
// `defaultBorders` (Spriteset.from). Deriving the choice here rather than
// hard-coding it per widget means adding borders to a frame changes its
// rendering with no code change — and it makes pixi's silent fallback
// unreachable, since NineSliceGeometry.defaultOptions would otherwise
// substitute 10 px insets for a texture that has none.
export function createBackground(texture: pixi.Texture): pixi.Container {
  return texture.defaultBorders === undefined ?
      new pixi.Sprite(texture)
    : new pixi.NineSliceSprite({texture});
}
```

- [ ] **Step 4: Write the implementation**

Create `source/engine/ui/resolveThemedBackgrounds.ts`:

```ts
import type * as pixi from 'pixi.js';

import {createBackground} from './createBackground.js';

// Builds a background per state, preferring an explicit override and falling
// back to the theme's texture for that state. An overridden state builds
// nothing from the theme: a discarded background would never be adopted for
// destruction, so it would leak.
export function resolveThemedBackgrounds<State extends string>(
  states: readonly State[],
  textures: Record<State, pixi.Texture> | undefined,
  overrides: Partial<Record<State, pixi.Container | undefined>> | undefined,
): Partial<Record<State, pixi.Container>> {
  return Object.fromEntries(
    states.map((state) => [
      state,
      overrides?.[state] ?? (textures && createBackground(textures[state])),
    ]),
  ) as Partial<Record<State, pixi.Container>>;
}
```

```ts
  // Every art entry is a [spriteset, frame] pair; everything else (focus-ring
  // padding, text styles) passes through. Runs after the default bundle loads,
  // so every frame named in the description must live in that bundle.
  #resolveTheme(description: UiThemeDescription): UiTheme {
    let resolveEntry = (value: unknown): unknown =>
      Array.isArray(value) ?
        this.#assets.texture(value[0] as never, value[1] as string)
      : value;

    return Object.fromEntries(
      Object.entries(description).map(([group, entries]) => [
        group,
        Object.fromEntries(
          Object.entries(entries as Record<string, unknown>).map(([key, value]) => [
            key,
            resolveEntry(value),
          ]),
        ),
      ]),
    ) as UiTheme;
  }
```
