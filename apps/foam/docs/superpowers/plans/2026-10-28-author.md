# The Author (Foam Phase 8, Spec 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jakub, the author's avatar, sits in one of three places for two hours of the night, picked
by the seed; a message at 16:30 says where; a "Jakub" button stands in that place during his hours
and opens a short meeting, and the first meeting anywhere finds the story "The author".

**Architecture:** A spot gains an optional `isVisible` on the night, which the night screen reads
when it shows a place and whenever it looks at the night, setting each button's `view.visible`; a
hidden button keeps its position and leaves the Tab order by itself. One module,
`content/author.ts`, holds the seats, the pick `authorTonight` and `isAuthorIn`, which the
invitation and the three places' buttons read, so the message and the place never disagree. The
checker runs a spot's condition on its place's check nights as it runs a choice's.

**Tech Stack:** TypeScript 6 (`exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`), Tellurion
(`Button`, `UiRoot`, `Dialogue`), `@pixi/layout`, Vitest 4 (`unit` in Node, `browser` in
Playwright's Chromium), Prettier 3, Turborepo.

**Spec:** `apps/foam/docs/superpowers/specs/2026-10-28-author-design.md`

Runs after spec 1 is built (`docs/superpowers/plans/2026-10-28-phone.md`): `Message` and `messages`,
`content/phone/sender.ts` and the twelve message files, `receiveArrivals` in `actOnNight`,
`createCheckNights` in the checker, the bottom row of 24, `waitForToast(harness, title)` and
`waitForNoToast` in the test helpers, and the phone's tests in `phone.browser.test.ts`,
`continue.browser.test.ts` and `content.test.ts`. The direction document already carries the Author
row and the phase 8 paragraph's second item (commit `cf987017`); the last task only states that the
spec is built.

Six things the spec implies but its file table or its examples do not say, settled here:

- **A hidden button has no box.** `@pixi/layout` takes an invisible container out of its tree: a
  button built hidden never gets a computed layout, and `getBox` reads zeros. The three fixed-bar
  tests that measure every spot button measure the visible ones, and the picture's things gain the
  regular's, so the tests that place every spot on its thing still run over all five.
- **The fixed world's regular keeps hours, 20:00 to 20:30,** not an open-ended `minutes >= 1200`:
  the spec's step 3 (the button goes when the next window closes) and its error table's focus row
  need a condition that stops holding, and the fixed bar has no cheap way past 21:00. His scene
  offers "Sit a while" for 30 minutes, which runs past his hours.
- **The invitation is every night's second message,** so the phone's browser tests, which count and
  read the messages of a night past 16:30, gain it: the quiet seed's keys, the counts, the saved
  lists and the reading order. Task 4 lists every change.
- **`content/phone/sender.ts` goes:** the twelve message files import `AUTHOR` from `author.ts`, as
  the spec's sentence on the phone's files says.
- **`scripts/list-stand-ins.mjs` lists `author.ts`,** which holds the story's title, or "Done when"
  cannot hold; the invitation is in the phone folder, which spec 1 lists, and the meetings in the
  location files.
- **The positions.** Computed over the three test screens with the bottom row in place, so no button
  overlaps another: the shop's Jakub at `x: 0.5, y: 0.65`, Rotor's at `x: 0.5, y: 0.75`, the hall's
  at `x: 0.3, y: 0.6`, the fixed bar's regular at `x: 0.45, y: 0.6`. The content test's overlap test
  holds the first three; `nightScreen.browser.test.ts` holds the regular.

  the nights where it can hold, and the count is one call per name per check night of that place.
  Pinned in Task 2.
