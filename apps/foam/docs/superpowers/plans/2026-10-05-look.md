# The Look (Foam Phase 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every Foam screen gets Foam's own look: one palette, UI art drawn by a script, black
windows with one-pixel borders, a rose focus ring, window titles with a rule, a text cursor, and
italic words in the story text.

**Architecture:** `core/palette.ts` is the one list of colours; a Node script imports it and draws
`public/ui.png` and `public/ui.json`, and a unit test proves the committed files equal the script's
output. The theme maps the new frames and paddings. The story window draws a page as two
same-sized text leaves (regular and italic) filled from the pure `splitMarked`, and puts a cursor
after the last letter shown. The menu, options, main menu and error screen are laid out again with a
shared title block.

**Tech Stack:** TypeScript, Node 24 (runs the `.ts` palette from an `.mjs` script), `fast-png`,
Tellurion (Pixi.js 8, `@pixi/layout`), Vitest 4 (`unit` in Node, `browser` in Playwright's
Chromium), Turborepo.

**Spec:** `apps/foam/docs/superpowers/specs/2026-10-05-look-design.md`

Runs after the pixel-scale plan (`docs/superpowers/plans/2026-10-05-pixel-scale.md`); the tests
here assume its rule, which gives scale 2 for the 960 × 540 and 292 × 524 test windows under both
rules.

## Global Constraints

- Only files under `apps/foam/` and the root `package-lock.json` change. Nothing under
  `apps/somewhere/` or `packages/tellurion/`.
- Files headed `DO NOT EDIT … autogenerated by Carson` (`vite.config.ts`, `tsconfig*.json`,
  `eslint.config.js`, `tests/tsconfig.json`) are not edited.
- No art is AI-generated. Every pixel of `ui.png` comes from `scripts/generate-ui-atlas.mjs`, which
  reads no image file.
- Palette, exactly: `black 0x000000`, `ground 0x1f1a2d`, `shade 0x2d2735`, `line 0x463c5c`,
  `dim 0x8479a0`, `white 0xffffff`, `rose 0xff1b64`, exported as `palette` with `as const`, in that
  order.
- Sizes in art pixels: button padding 2 above and below, 6 left and right; button height 16; window
  padding 8 above and below, 12 left and right; title block 12 + 2 + 1 = 15, then a gap of 4; 8
  between the text and the first choice; 4 between two buttons in a window; story window at most
  300 wide; scrim black at 0.6; focus ring padding 2; slider 64 × 8; cursor 5 × 9.
- The font stays monogram, 6 × 12 per letter. Theme roles `label` and `body` are both `monogram`,
  size 12, `white`. Only the status line uses `monogram-outline`. `monogram-italic` is loaded; the
  outlined italic is not.
- A `*` in a node's `text` toggles italic. Marks are never shown and are not read in speakers or
  choices.
- Code style: `let` for locals, `const` only at module level; relative imports end in `.js` in
  `source/` and `tests/` (the script imports the palette as `../source/game/core/palette.ts`);
  comments say why, within 100 columns; a blank line between declarations and other statements.
- Lint: `npx eslint <files>` must report 0 errors. Known warnings that stay: hyphenated asset keys
  in `assets.ts` (the new `'monogram-italic'` key adds one), `.catch(1)` in `settings.ts`, `_resolve`
  in `bootFailure.browser.test.tsx`, a module-level `let` in `settings.browser.test.ts`.
- Tests: the `vitest` object, not `vi`; no `expect` inside `beforeAll`/`beforeEach`; a test file
  without JSX is `.ts`; no test file imports a game module at its top (`bootGame` imports them after
  the viewport is set). Modules free of `game.ts` (`palette.ts`, `markedText.ts`, `getSceneArea.ts`,
  `theme.ts`, `samplePlace.ts`) may be imported at the top.
- Browser tests run at pixel scale 2 and are slow (frames of 100–250 ms, a real tap about 3.5 s).
  Keep the existing `describe` timeouts; a test that waits for text to type by itself has a 120 s
  timeout.
- Before the first browser run: `npx turbo run build --filter=tellurion`. A first run after a
  dependency change can fail on "optimized dependencies changed"; run it again before treating it
  as a failure.
- Commands run from `apps/foam` unless a step says otherwise. Commit at the end of each task; a
  message is one short imperative sentence, no prefix, no trailer.

## Review Focus

- **A page that starts inside an italic passage.** A long italic phrase broken by a page end must
  stay italic on the next page. Pinned by the `splitMarked` "starts inside italic" unit test
  (Task 1) and by the browser test that the page after `*Nobody*` is not italic (Task 3).
- **The cursor after a full line, and on a page that ends with a line end.** A full 46-letter line
  puts the cursor 7 pixels past the text; a page followed by another ends with `\n`, which must not
  move the cursor to an empty next line. Both pinned in Task 3.
- **Marks and the typewriter.** A mark is a revealed character that shows nothing and must not
  blip, must not change wrapping, and must not appear in `StoryWindow.text`. Pinned in Task 3 (the
  shown text equals the stripped page text; no line exceeds the text width when measured without
  marks).
- **The committed art drifting from the script.** Pinned by the atlas test (Task 2), which also
  checks that every opaque pixel is a palette colour, so a hand edit of `ui.png` fails.
- **The focus ring touching a neighbour.** Buttons 4 apart and a ring 2 out leave a gap; pinned by
  the menu gap test and the ring bounds test (Task 4).

### Task 1: Reading italic marks

**Files:**

- Create: `source/game/core/markedText.ts`
- Create: `tests/markedText.test.ts`

**Interfaces:**

- Produces:
  - `stripMarks(text: string): string` — the text without `*`.
  - `splitMarked(text: string, start: number, end: number): {regular: string; italic: string}` —
    for `text.slice(start, end)`; italic is on at `start` when `text.slice(0, start)` holds an odd
    number of marks. Each result has one character per non-mark character of the piece: the letter
    in the active font's string and a space in the other; `\n` is kept in both. A mark toggles and
    adds nothing. Doc comments as in the spec.

- [ ] **Step 1: Write the failing tests**

`describe(stripMarks, …)`:

- `stripMarks('the beer was *better* then')` is `'the beer was better then'`.
- `stripMarks('no marks')` is `'no marks'`.

`describe(splitMarked, …)`, with `const TEXT = 'a *bc* d'`:

- no marks: `splitMarked('ab c', 0, 4)` is `{regular: 'ab c', italic: '    '}`.
- one italic word: `splitMarked(TEXT, 0, 8)` is `{regular: 'a    d', italic: '  bc  '}`.
- two italic words: `splitMarked('*a* b *c*', 0, 9)` is `{regular: '  b  ', italic: 'a   c'}`.
- a piece that starts inside italic: `splitMarked(TEXT, 4, 8)` is `{regular: '  d', italic: 'c  '}`.
- a piece that ends inside italic: `splitMarked(TEXT, 0, 4)` is `{regular: 'a  ', italic: '  b'}`.
- line ends stay in both: `splitMarked('*ab*\ncd', 0, 7)` is `{regular: '  \ncd', italic: 'ab\n  '}`.
- both results as long as the piece without marks: for every `start ≤ end` over `TEXT` and over
  `'*ab*\ncd'`, `regular.length` and `italic.length` equal
  `stripMarks(text.slice(start, end)).length`.
- an odd number of marks: `splitMarked('a *bc d', 0, 7)` is
  `{regular: 'a     ', italic: '  bc d'}`.
