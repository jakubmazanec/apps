# The Seed (Foam Phase 7, Spec 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** A night is a whole number, today's date by default or one typed into the window New Game
opens or given by the jump-in's `seed=`; everything the night decides, the start money and every
roll of the dice, is a hash of that seed and a key, so two players with one seed play one night; the
log's first line names the seed; and the checker meets every branch on `random` through six values.

**Architecture:** `core/hash.ts` is cyrb53 over the seed and a tagged stream of keys, with no
dependency. `createNight` sets `night.random` to that hash of the night's seed and draws the money
from a range with it; `roll` reads `('roll', count)`. The start carries a `seed` that the New night
window and the jump-in write. The checker gives every check night a `random` that notes it was read,
and runs a function that read it five more times with the other values.

**Tech Stack:** TypeScript 6 (`exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`), Tellurion
(`Modal`, `Panel`, `TextInput`, `Button`), Vitest 4 (`unit` in Node, `browser` in Playwright's
Chromium), Prettier 3, Turborepo.

**Spec:** `apps/foam/docs/superpowers/specs/2026-10-25-seed-design.md`

Runs after phase 6, which is built: `night.quest`, the stories, the endings and the sleep choices,
and the checker over the sixteen quest states. The direction document already carries the spec's
Seed, Variation and Saving rows and the phase 7 paragraph (commit 39c62e65); this plan only states
that the spec is built.

- Tests: the `vitest` object, not `vi`; a blank line separates a group of `expect` lines from other
  statements; `describe(fn, …)` when named after a function; no `expect` inside `beforeAll` or

  `content/nightStart.ts` and the New night window call `todaySeed`.
- Exact values from the spec: a seed is a whole number of 1 to 15 digits; the default is
  `getFullYear() * 10000 + (getMonth() + 1) * 100 + getDate()` of `new Date()` in local time; the
  content's range is `{min: 300, max: 500, step: 50}`; the money key is `'money'`, the dice key is
  `'roll'` with the count of rolls so far; `CHECK_RANDOM` is `[0, 0.2, 0.4, 0.6, 0.8, 0.99]`; the
  check nights have a seed of 0; the jump-in's warning is
  `The jump-in ignores the seed "${value}": it is a whole number of up to 15 digits.`; the window's
  title is `New night`, its label `Seed`, its buttons `Start` and `Close`; the field has
  `maxLength: 15` and no placeholder; the log's first line is `Seed ${night.seed}`, then a blank
  line.
- The hash's constants are cyrb53's, so the pinned values below hold in every browser and in Node:
  `h1 = 0xdeadbeef`, `h2 = 0x41c6ce57`; a word mixes as `h1 = Math.imul(h1 ^ word, 2654435761)` and
  `h2 = Math.imul(h2 ^ word, 1597334677)`; the finish is cyrb53's four lines; the 53-bit integer is
  `4294967296 * (2097151 & h2) + (h1 >>> 0)`, divided by `2 ** 53`.

## Review Focus

- **Leading zeros.** `007` typed into the field, or `seed=007` in the address, is the seed 7, and
  the log says `Seed 7`. Pinned in Task 4 (the field) and Task 5 (`getJumpIn`).
- **A step that does not divide the range.** `{min: 300, max: 500, step: 70}` draws 300, 370 or 440,
  never 510: the count of steps is `Math.floor((max - min) / step) + 1`, not the spec's
  `(max - min) / step + 1`, which would let `Math.floor` reach one past the range. Pinned in Task 2.
- **Midnight.** The page loaded before midnight and New Game pressed after it: the window reads the
  clock when it opens, so the field shows the new day. Pinned in Task 1 (`todaySeed` reads the clock
  at each call) and Task 4 (the window is built per open and calls it there).
- **The checker's random after a roll.** A rolled choice puts a constant `random` on its check night
  for the hundred rolls; a text checked after it still fans out over the six values because the
  night's own `random` is put back. Pinned in Task 3.
- **A jump-in night quit and New Game pressed.** The window's date replaces the jump-in's seed, and
  the jump-in's place, hour and money stay. Pinned in Task 5.

The mixing is pinned here because the test values depend on it. Two 32-bit halves mix every word:

```ts
let mix = (word: number): void => {
  h1 = Math.imul(h1 ^ word, 2654435761);
  h2 = Math.imul(h2 ^ word, 1597334677);
};
// A whole number as its two 32-bit halves: a seed of 15 digits is wider than 32 bits.
let mixNumber = (value: number): void => {
  mix(value >>> 0);
  mix(Math.floor(value / 2 ** 32) >>> 0);
};
```

`mixNumber(seed)` first; then for each key: a number mixes `1` then `mixNumber(key)`, a string mixes
`2` then each `key.codePointAt(index) ?? 0` in order (lint prefers code points; the same number as
the character code for every key the content has); then `0`, the boundary tag. Then cyrb53's finish
(`h1 = Math.imul(h1 ^ (h1 >>> 16), 2246822507); h1 ^= Math.imul(h2 ^ (h2 >>> 13), 3266489909);`
`h2 = Math.imul(h2 ^ (h2 >>> 16), 2246822507); h2 ^= Math.imul(h1 ^ (h1 >>> 13), 3266489909);`) and
the 53-bit integer of the Global Constraints divided by `2 ** 53`. Every step is exact in doubles,
so `toBe` holds across engines.

### Task 3: The checker meets every version

**Files:**

- Modify: `source/game/core/checkContent.ts`

**Interfaces:**

- Consumes: `createNight` with `seed: 0` (Task 2); `roll`.
- Produces: `checkContent` with the same signature and lines. Module level gains
  `const CHECK_RANDOM = [0, 0.2, 0.4, 0.6, 0.8, 0.99];` under the spec's comment. Inside
  `checkContent`: `let randomRead = false;`, `createRandom(value: number): Night['random']`, a
  function that returns `value` and sets `randomRead`, and

```ts
// Calls the function with the night and, when it read random, with a copy of the night for each
// other check value, so every side of a split on random is met. Each result comes with the night
// that gave it, for the check to go on with that night.
function withRandom<T>(night: Night, call: (night: Night) => T): Array<{night: Night; result: T}> {
  randomRead = false;

  let results = [{night, result: call(night)}];

  if (randomRead) {
    let own = night.random();

    for (let value of CHECK_RANDOM) {
      if (value !== own) {
        let copy = {...night, random: createRandom(value)};

        results.push({night: copy, result: call(copy)});
      }
    }
  }

  return results;
}
```

Every check night built in `checkScript` gets `night.random = createRandom(0)`. The content's
functions go through `withRandom` wherever the checker calls one with a night:

- `text`, when a function: in a `try`; a throw adds `${path}: throws "${message}"` as `follow` does;
  each result's pages are split as today.
- `onEnter` and `onChoose`: `checkEffect`'s loop body becomes the arrow passed to
  `withRandom(night, …)`, with the fresh night built from the arrow's night (its `random` and `roll`
  copied over as today) and `continue` becoming `return`.
- `isVisible`, in the way-out check: a choice is always visible when `choice.isVisible` is undefined
  or every result of `withRandom(night, (source) => choice.isVisible?.(source) ?? true)` is true, on
  every night.
- `odds`, when a function: each `{night: source, result: chance}` is validated as today, and the
  rolled `next` loops `CHECK_ROLLS` on `source`, after `let {random} = source;` and with
  `source.random = random;` after the loop, under a comment that a function checked after the roll
  reads the night's own `random` again. A number `odds` and a missing one give one pair with the
  check night.
- `follow`: `withRandom(night, reference)` inside the `try`; each `{night: source, result: target}`
  is handled as today, an inline node checked with `[source]`.
- `start`, when a function: each `{night: source, result: node}` with an object node is checked with
  `[source]`; the call is in a `try`, a throw adding `${name}${SEPARATOR}start: throws "…"`.

A night's `random` set to a constant for the rolls notes nothing, so a `next` under a roll runs
under the hundred values and not six more; the roll's `rolls` count on the check night is harmless.
